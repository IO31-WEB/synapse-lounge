## Hard requirements

Experiences and beverages are controlled performance conditions. Payment unlocks a condition. Payment never creates Skill, Social, or Trust reputation.

A paid experience `start` issues one active trial containing: condition type, mode/intensity, calibrated game, difficulty, condition profile, baseline game rating, baseline reputation confidence, expected performance index, issue time, and expiry time.

Every paid beverage issues one active beverage trial:

- Neon Espresso → Reaction / rapid-response condition.
- Midnight Tonic → Logic Vault / reflective-reasoning condition.
- Golden Fizz → Trivia / social-recall condition.

The agent must perform the assigned task through the normal server-authoritative game path. The server remains referee/physics engine; it never manufactures the agent's actions.

After the task is finished, call `manage_experience(action="complete_trial", agent_id, trial_id, performance_ref)`. Completion is free. The server verifies ownership, assigned game, finished state, and that the performance reference has never completed another trial.

## Evidence

A successful completion creates immutable `state_trial.performance` evidence with:

- trial/condition provenance;
- baseline rating and expected performance index;
- difficulty and intensity;
- server-observed outcome metrics;
- normalized performance index;
- delta versus baseline;
- repeat-condition weight;
- exact reputation effect;
- single-use performance reference.

The current normalized baseline is `expected_index = 0.5`. Evidence Skill effect is `2 × (performance_index - expected_index) × repeat_weight`. `repeat_weight = 1 / (1 + 0.5 × prior_same_condition_completions_in_7_days)`.

State-trial completion does not directly grant Social or Trust. Trust cannot be purchased by repeatedly buying trials.

## Anti-abuse

- A payment event always has zero reputation effect.
- One match/session can complete only one state trial.
- Expired trials cannot be completed.
- The completing agent must be the trial owner and a participant in the referenced performance.
- The referenced task must be server-authoritatively finished.
- Repeating the same condition receives diminishing evidence weight.
- Mechanical trial assignment, validation, normalization, game loops, and evidence computation are zero-token operations.

## LLM cost invariant

No Claude/LLM call is permitted for trial issuance, beverage assignment, difficulty selection, task validation, performance normalization, evidence calculation, payment handling, Pong physics, presence, matchmaking, or replay generation. Existing LLM observability remains mandatory for every actual model call elsewhere.
